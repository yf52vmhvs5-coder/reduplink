================================================================================
NEBULA VOID — MULTIPLAYER
================================================================================
Ultima actualizare: 25 octombrie 2026
Stare: duelul se poate juca. Esc din meci e în lobby. Singleplayer nu folosește Esc.
       Relay-ul e filtrat (allowlist, ping, rate-limit). Simularea rămâne pe client.

Model (nu e server autoritativ):
  • Fiecare client rulează aceeași simulare ca PLAY.
  • server/index.js e un relay WebSocket. Nu simulează jocul.
    Nu mai copiază tot JSON-ul: trece doar tipurile de meci/lobby, cu câmpuri cunoscute.
  • Cameră: 2–6 jucători (game-data.js → multiplayer.minPlayersToStart / maxRoomPlayers).
  • Sincronizat: poziția, raza, skin-ul, cooldown-ul și evenimentele de duel.
  • Nutrienții verzi sunt locali. Praful stelar (cele 200) și dreptunghiurile din duel sunt aceleași.
  • Jeleul moale rămâne doar în singleplayer. În duel, în locul lui sunt 8 dreptunghiuri.

PLAY rămâne separat.
  runMode "single". La moarte: #gameOver clasic, VOID MATTER EARNED, materia se salvează.
  Butoanele RETRY / CHANGE ENTITY intră pe calea singleplayer doar când nu e card de duel.
  Esc nu închide un meci singleplayer.

================================================================================
LIMITĂRI
================================================================================

  • Cel mare crește când ajunge hitAck-ul (cam 100ms), cu exact px pe care i-a pierdut cel mic.
  • Rift-ul de bază stă pe loc. Cel din rift pierde raza pe loc; casterul primește jumătate
    la riftAck (~100ms). Sub rază 5, rift-ul omoară, fără bonusul de înghițire.
  • Cardul învinsului apare după explozia de 2,5s. Învingătorul își vede cardul imediat.
  • Esc nu există în singleplayer. În duel nu închide cardul de la final; acolo sunt butoanele.
  • START MATCH nu pornește singur după RETRY sau Esc. Hostul îl apasă din lobby.
  • Dacă cineva pleacă în cele 2,5s de explozie, cardul rămas e OPPONENT DISCONNECTED.
  • Hostul poate apăsa START în timp ce alții sunt încă în meciul vechi.
    Cine e deja în arenă ignoră al doilea matchStart. Non-hostul nu-l mai poate trimite prin relay.
  • Reconnect în timpul meciului nu există. Starea nu e pe server.
    Un disconnect = ieșire din cameră (lobby: RELAY LOST). Nu reintri în arena veche.
  • Rate-limit-ul de state e peste ritmul onest (16ms ≈ 62 Hz). Nu taie un client legitim.
    Un flood e plafonat; interpolarea ține celula, nu o teleportează la fiecare pachet în plus.

PROTOCOL
================================================================================

  Lobby: join | joined | peerJoined | peerLeft | error
         join.create = true doar la CREATE. join.public = true → cameră vizibilă.
         JOIN fără cameră → error NO_ROOM. CREATE public peste cap → PUBLIC_FULL.
         peerLeft include hostPeerId (noul host, dacă cel vechi a ieșit).
         chat { text, t }
         lobby {}           — abonare la lista publică (fără a intra în cameră)
         leave {}           — iese din cameră, rămâne pe socket, primește roomList
         roomIdle {}        — camera publică revine în listă după meci
         roomList { rooms:[{ roomId, host, n, max }] }

  Meci:
    matchStart   { t0, roomId?, peerOrder, dustSeed }
                 relay: doar de la host. Restul se aruncă.
    dust         { eats:[{ id, s }, ...] }   — până la 24 mâncăruri din același frame
                 sau legacy { id, s }
                 s = secunda de meci a înlocuitorului
    egg          { eats:[{ id, s }, ...] } sau legacy { id, s }
                 slotul reapare la rând, fără alt mesaj
    cast         { kind:"vampire"|"warp"|"speed", t, x, y, seq }
                 un pachet per Space. Relay: 6/s, burst 3.
                 Efectul pornește local la primire (rift fix, shriek, dash).
    riftAck      { t, amount, ownerPeerId }
                 îl trimite victima, ~10/s. amount = px pierduți de la ack-ul anterior.
                 ownerul adaugă amount/2 dacă victima e lângă riftul lui.
                 Relay: 15/s, burst 4, amount ≤ 20.
    state        { t, x, y, radius, ability, cd, cdMax }
                 + color, glow, entity la full (start, schimbare skin, keepalive 300ms)
                 x/y ≈ 0.1px; radius/cd ≈ 0.01
                 dropIfBuffered dacă socket.bufferedAmount > 8KB
    claimHit     { t, kind:"eat", targetPeerId, x, y, radius }
                 îl trimite cel mare, cel mult o dată la 100ms, cât vede contact
    hitAck       { t, kind, targetPeerId, amount?, eatenRadius? }
                 kind "drain" — amount = px pierduți de victimă de la ack-ul anterior
                 kind "kill"  — eatenRadius, plus amount pentru contactul încă neconfirmat
    respawn      { x, y, radius }     — re-enter după moarte
    eliminated   { byPeerId, killerCallsign }
    forfeit      { esc?: true }
                 esc true  = a apăsat Esc; celălalt vede OPPONENT DISCONNECTED
                 fără esc  = a părăsit de pe cardul de moarte; cel viu poate câștiga
    matchEnd     { entity, winnerCallsign, winnerPeerId }

  Server (server/relay-packets.js + server/index.js):
    allowlist pe tip + copiere explicită de câmpuri; fromPeerId e pus de server
    state: token bucket 70/s, burst 12
    ping 15s, maxPayload 4096, perMessageDeflate oprit
    un stringify pe cameră, apoi send raw la ceilalți
